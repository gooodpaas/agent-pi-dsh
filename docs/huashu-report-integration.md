# huashu-report 在 Agent Pi DSH 中的接入

研究日期：2026-09-15。来源为[作者文章](https://www.toutiao.com/article/7685398706316902927/)及[源代码](https://github.com/alchaincyf/huashu-report/tree/bdc08bee5077462e1300431408c5237438a22d00)。本文依据固定提交的 SKILL.md、研究深度/生产流水线参考资料及图表、渲染脚本，不把文章的宣传性性能比较当作实测结论。

## 值得引入的能力

它是一套报告编制方法和本地脚本，不是新的模型或云端报告服务。最有价值的顺序是：明确读者要做的决策 → 建立可核对的证据数据表 → 解释机制和适用边界 → 组织报告 → 制作图表 → 检查实际文件。

| 能力 | 对专业工作台的意义 | 使用边界 |
| --- | --- | --- |
| 数据表记录 ID、数值、口径、样本/分母、来源及核验状态 | 减少正文、图表与数据口径相互矛盾 | 工程量、合同额、工期采用相应单位与依据，不强制套调查样本 N |
| 区分资料整理、机制解释与既有研究比较 | 可研、技术分析、风险报告需回答“为什么”与“怎样使用” | 事实不足时保留缺口；不得编造引用、参数或核验状态 |
| 结构、图表编号、来源行与视觉系统 | 长报告保持一致，图表服务比较而非装饰 | 用户模板与招标要求优先，非所有报告都适合咨询 deck |
| 成对柱、折线、发散条等 SVG 图表 | 适合技术、经营、进度等数据表达 | 检查负数、零值、轴范围与标签，不能只看脚本返回成功 |
| HTML/PDF 渲染、目录页码迭代回填、机械和几何检查 | 降低目录失配、越界、占位符残留等问题 | 仍需逐页看图；不能据此宣称计算与专业结论已验收 |

上游中的研究员、编辑、信息设计师、可视化师在这里是工作阶段，不要求固定创建四个子智能体。参考资料按需读取；示例语料不作为当前项目的事实来源。

## 普通对话如何使用

用户要求“编制可研报告”“修订调研报告”“起草技术标”等实际创作任务时，产品扩展在原生请求组装前添加短引导，由 DSH 原生 `skill` 工具加载 `huashu-report`。无需启用专业深度或建立投标项目。未命中规则的表达仍可由原生技能目录按描述选择，用户也可明确点名技能。

仅提及报告、总结已有报告、询问如何写报告、报告打不开等情况不通过本产品规则启动创作。规则只看用户消息，忽略引用块、代码块和工具消息；它是轻量规则，不能保证涵盖所有表达，因此不应作为强制流程门禁。

已有信息足够时直接执行。仅关键用途、对象或交付要求缺失且无法合理推断时集中询问。过程语言跟随用户输入，不展示内部角色讨论或安装日志。

专业深度是独立的用户选择：开关只保存状态，实际发任务才工作。复用模板仅由用户编辑后保存、主动选用；不会因为用了报告技能就自动沉淀、召回模板或加载全部知识库。

## 投标报告的取舍

招标文件、补遗、评分表、指定目录和用户模板决定合规格式，`tender-formal-writing` 优先处理正式投标写作要求。本技能提供证据、逻辑、图表与自检方法。不能为了通用美观规则删减必交章节、限制法定附件比例、改动表格或将技术标替换为幻灯片。

要求可编辑 Word 时交付实际 DOCX，继续使用 Univer Office；HTML/PDF 不替代 DOCX。成果和过程产物仍通过当前工作目录、文件栏及 DSH 原生交付机制查看。

## 本地运行与发行

完整技能、参考资料、图表库和样式随产品 `skills/huashu-report` 打包，由现有 `DSH_BUNDLED_SKILL_DIR` 加入原生技能目录。MIT 原始 LICENSE 和来源提交保留；应用发行许可证保持 GPL-3.0-only。

基础写作和 SVG 不需要云端渲染。上游 PDF 流程需要 Python 3、Python Playwright、Chromium，以及 Poppler 的 pdfinfo、pdftotext、pdftoppm；它们不因复制技能文件就自动存在。先运行随技能提供的 `assets/check_runtime.py`，按实际环境使用现有 Office/PDF 工具或补齐本地依赖。应用启动不自动安装这些工具。

本次将 render.py 的 HTML 地址改为标准 file URI，适配 Windows、中文和空格路径；生成器及 PDF 文本提取显式使用 UTF-8，提取命令失败会直接报错。原始资料保留，产品适配集中于 `AGENT-PI-ADAPTATION.md`，不修改官方 DSH 内核来实现报告流程。
